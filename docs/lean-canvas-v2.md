## 1. 总体诊断：v1 画布的四道结构性裂缝

**裂缝 A · 画布描述的是「产品」，不是「生意」。**
九格里七格在讲你造了什么（skills / agent / 工具链），只有「收入来源」在讲钱，而它是想象。
这正是《精益创业》反复警告的顺序错误：**解决方案先行**。Maurya 的规矩是先做 20–30 个问题访谈，再动「解决方案」这一格。

**裂缝 B · 「关键指标」是空的。**
这是整张画布上唯一能告诉你「有没有在进步」的格子，也是「创新核算」的唯一载体。没有它，画布只是海报，不是仪表盘，也就没有 pivot 的判据。

**裂缝 C · 「客户群体」一栏装了两个不同的生意。**
高校硕博课题组 vs 企业工作室：痛点不同、预算不同、决策链不同、成功定义不同、销售周期不同。
**一个 MVP 不可能同时服务两者。** 精益创业里最常见的死法，是被「容易获得的客户」的掌声骗过去——课题组容易触达、会给你赞美、但不给你钱，而且它的成功标准（能毕业/能发论文）和商业客户（能上评审会/能开模）根本不是同一件事。

**裂缝 D · 交付形态与客户能力自相矛盾（最致命）。**
- UVP 说「聊聊天就能设计」——面向**不会的人**；
- 可交付链路要求：DSH 宿主 + 本机 NUMECA 正版授权（几十万级）+ 能跑三维 CFD 的机器 + 看得懂结果的人。

**「不会的人」装不了这条链，也看不懂输出。** 这个矛盾不解决，UVP 就是空头承诺。三条出路：

| 出路 | 形态 | 客户是否需装工具 | 变现速度 | 我的判断 |
|---|---|---|---|---|
| (a) 卖结论（代跑 / 交钥匙） | 服务 | 否 | 快（30 天内可收钱） | ★ MVP 首选 |
| (b) 卖给已有工具链的组织 | 私有部署 + 订阅 | 是 | 中（3–9 个月） | 扩容期主力 |
| (c) 云 SaaS 席位 | 自建云 | 否 | 慢 | **授权未解决前只是假设，不是计划** |

## 2. 逐格改写

### 格 1 · 问题（原：1.没人会 2.来不及 3.算不准）

问题写法太抽象，没有优先级、没有钱的味道。改成**客户会用自己的话说出来**、且能按掏钱意愿排序的形式：

| 优先级 | 痛点 | 客户原话 |
|---|---|---|
| P0 | **能力断层** | 「师兄毕业了/招不到人，组里没人会 CFD，从头学要一年」 |
| P0 | **交期压死** | 「老板下周要看结果，等超算排队、等外包、等师兄，来不及」 |
| P1 | **结论不可信** | 「算出来了，但我说不清为什么；评审一问网格无关性和收敛判据就崩」 |
| P1 | **不可复现** | 「同一个算例，我做的和他做的结果不一样，没人知道哪个对」 |
| P2 | **沉没成本** | 「设计错了要重新开模/重新试制，一次几万到几十万」 |

**现有解决方案（补上最危险的三个竞争者）**

- 花钱招人 → 招不到；人走了，知识跟着走
- 靠老师傅经验 → 不可规模、不可审计、不可复现
- 商业软件自带模板 → 模板给你几何，不给你**判断**；出问题还是靠人
- ★ **外包代做**（漏了，而且它最危险）→ 结果不可追溯、改一次再收一次钱、知识不留在客户手里。**但它同时证明了这个需求有预算——而且它就是你 MVP 的形态。**
- ★ **通用大模型 + 一个懂行的人**（漏了，增长最快的替代品）→ 差异化必须建立在「有正式工具链、有可审计证据链」上，通用模型给不了
- ★ **什么都不做，继续拍脑袋**（最普遍的那个）

### 格 2 · 客户群体（原：1.高校硕博课题组 2.企业工作室）

**必须选边。**

**先做（收入来源）**：**小型叶轮机械硬件团队**
- 具体画像：5–30 人；有 1 名气动工程师，或干脆没有；每年 2–5 个新叶型/新机型；单次试制预算 5–50 万；正在用 SolidWorks + 外包 CFD，或者在自学 OpenFOAM
- 典型行业：eVTOL/无人机涵道风扇、小型涡喷/涡扇、鼓风机压缩机、通风散热、泵与水轮机

**早期采用者（更窄、更硬的定义）**：
**已经吃过一次「设计错了要重开模」的亏，且下一次节点在 3 个月内**的团队。
（不是「高校课题组」——那是**容易触达**，不是**早期采用者**。早期采用者的定义是：有痛点、有预算、有截止日期、并且愿意容忍不完美。）

**战术性保留**：你所在高校/圈子里有真实课题节点、且愿意签验收单的课题组——**用来练手、积累案例库、做传播，不作为主要收入来源**。

**明确不做（12 个月内）**：大型 OEM 气动室（他们有全套工具和人）、纯教学用户、个人爱好者。

### 格 3 · 独特价值主张（原：聊聊天就能设计出优秀的叶轮机械）

原句有两个问题：**「优秀」不可验证**；**「聊天」低估了价值**。

**主句（有时间、有数字、可验证）**
> 把「我想要一台 XX kgf 的风扇」做到一份**能上评审会的 CFD 结论**——5 天、全程可追溯、每一步都有判据。

**副句（这才是真正的差异化）**
> 你不用会 CFD；但你的结论**经得起会 CFD 的人查**。

**10x 在哪**：不是「算得快」（商业软件也算得快），而是
**从「必须有人会做」到「不需要有人会做」**，外加**从「一坨结果」到「一条能自证的证据链」**。

**对客户说的类比**
> 「给你的气动团队配一个不知疲倦的初级工程师，外加一个从不放过错误的审核员。」
（原句「工业设计软件的智能编排助手」偏工具视角，客户听了不知道省了什么。）

**明确不承诺什么**（写进 UVP 边界，避免过度承诺）
不承诺一次成功；不替代 CFD 工程师做最终判断；不替代试制前的人工评审。

### 格 4 · 解决方案（原：1.可组合skills 2.自然语言驱动，小白可上手 3.可审计工作日志）

内容是对的，**顺序错了**——「可组合 skills」是**实现**，不是客户能感知的价值。按客户视角重排：

1. **一句话需求 → 结构化需求单**：把「我想要 90 kgf」变成带算式的设计大纲，并把「算不了/信息不足」如实说清（你的 HANDOFF 里那 10 条未决问题就是这个能力的证据）
2. **方案与几何自动生成**：1D 通流 → 叶型 → geomTurbo
3. **网格与求解全自动**：AutoGrid / FINE，含质量报告与收敛判据
4. **交付三表 + 一页结论**：性能表、几何表、流道表 + 可直接进 PPT 的图
5. **全程可审计**：每个产物有版本、哈希、上游、判据、结论；任何一步都能回放复现（★ 这条才是护城河的入口，不是第 1 条）
6. **可组合 skills**：客户可以只要其中一段——例如只买「复核你现有的算例」

### 格 5 · 关键指标（原：空白 —— 这是最要命的洞）

**A. 北极星（度量价值假设）**

| 指标 | 定义 | 目标 | 当前基线 |
|---|---|---|---|
| 端到端中位周期 | 收到一句需求 → 客户接受交付 | ≤ 5 天 | DF90-001 的 G0→G5 约 2 天，但 G6 未闭环，暂不可计 |
| 一次通过率 | 无需人工救火即可走完全链的算例比例 | ≥ 70% | 未测 |
| 客户接受率 | 交付被客户签字接受 / 总交付 | ≥ 80% | 未测（尚无客户） |

**B. 引擎指标（度量增长假设）——选黏性引擎（sticky）**
- ★ **追加率**：同一客户 90 天内提交第二个算例的比例。这是 B2B 工程服务里**最诚实**的增长信号，且无法伪装。
- 转化漏斗：内容触达 → 留资 → 免费试算 → 付费算例 → 追加

**C. 创新核算（每 2 周一次，30 分钟，写进 LOG）**

| 项 | 内容 |
|---|---|
| 基线 | 3 个真实客户各自的周期 / 一次通过率 / 接受率 |
| 调优 | 这周改了哪条 skill 或判据，指标动了多少 |
| 决策 | **坚持 / 转向**（pivot 类型：客户细分 pivot？渠道 pivot？价值捕获 pivot？） |

**D. 反虚荣指标清单（明确不看）**
star 数、skills 下载量、公众号阅读量、token 消耗、跑过的算例总数，
以及——**agent 自己报告「已完成」的次数**。
**agent 说完成了不算完成，客户签字才算。**

### 格 6 · 不公平优势（原：1.气动知识+agent工程+工业工具链 2.跑通真实项目 3.自媒体信任资产）

**先说难听的**：原三条里，前两条是**能力**和**证据**，不是护城河。任何能被一个足够强的团队在 6 个月内复制的东西，都不是「不公平优势」。「自媒体信任资产」目前是 0（仓库无 remote、无发布痕迹）。

**真正的护城河候选——判据是「越用越厚，且抄不走」**：

1. ★ **私有验证基准库**（唯一带复利的资产）
   v7 的 45 个验收点 + NASA 双级 900 点 + Rotor67 + DF90-001 全程。
   **带真值的私有数据**，同时充当：模型标定、以及「这台机器算得对不对」的自动判据。
2. ★ **验收判据库（闸门库）**
   知道「什么结果不能信」比「能算出来」稀缺得多，且只能靠真项目一条条攒。
3. **全链关键环节自研**：turbo-flow(1D/S2) + cascade-forge(造型) + 自己的编排层 —— 不是黑盒调用者。
4. ★ **每个客户都是数据入口**：客户做得越多 → 基准库越厚 → 一次通过率越高 → 交付成本越低。**这是唯一能形成正反馈飞轮的结构。**
5. **自媒体信任资产**：现在是 0；只有持续发布才成立。成立后它同时是渠道和护城河。

**要如实承认的软肋**（写进画布，不要藏）
- 核心求解器不是你的（NUMECA）
- agent 编排能力正在被通用模型快速拉平
- 你只有一份时间——这是所有服务型 MVP 的天花板

### 格 7 · 渠道（原：1.自媒体 2.学术圈口碑）

方向对，但要具体到「能算出转化率」：

1. **自媒体（内容即产品演示）**
   不要发「我做了个 agent」，要发**带真值的过程复盘**：
   「我用 AI 把一台 90 kgf 涵道风扇从需求做到 CFD 结论，第 3 天我发现自己犯了什么错」。
   平台：B站（录屏）/ 知乎 / 公众号长文；硬件初创密度高的话加小红书。
   路径：内容 → 留资 → 免费试算。
2. **★ 学术圈口碑（你独有、别人拿不到的渠道）**
   你手里有 CompAI（AST 投稿中）+ DeepDelta-Aero（NASA 数据）——**论文本身就是产品的可信度证明**，而且直接触达高校与企业里的技术决策人。
3. **工具链生态**：NUMECA/Ansys 的代理商与培训渠道——他们卖软件，你卖「买了软件以后还是没人会做」的那一段。
4. **硬件加速器 / 孵化器 / 低空经济产业园**：目标客户密度高。
5. **案例客户转介绍**：把「介绍一个人」写进验收单。

**渠道原则**：每条渠道必须能算出「触达 100 人 → 几个留资 → 几个试算」。**算不出来的渠道先不做。**

### 格 9 · 收入来源（原：短期 skills包订阅+算例代跑 / 中期私有部署 / 长期 saas席位+算例代跑）

**排序有内在矛盾，要重排：现金流优先，而不是想象力优先。**

**第 0 期（0–3 个月）· 算例代跑 / 交钥匙交付** —— 验证 + 现金流
- 计价按**「结论」而不是按机时**
- 锚点：外包 CFD 一个涵道风扇算例市场价数千到数万；你的定价落在「比外包便宜 30–50%，比自己做快 5 倍」
- 起步节奏：**首单免费或成本价**（换验收单 + 案例公开授权）→ 第二单 5,000–15,000 元/交付 → 复杂机型 3–8 万
- **为什么先做这个**：一次拿到三样东西——现金、真实需求、基准库数据

**第 1 期（3–9 个月）· 订阅式「气动外脑」**
- 2–5 万/年，含 N 个算例 + 随时问答 + **复核你已有的算例**
- 卖的是「随时能问、随时能救火」，黏性最强的一层

**第 2 期（9–18 个月）· 私有部署 + 定制**
- 客户有 license、有机器、有保密需求 → 装进客户内网，部署费 + 年费（10 万级）
- ⚠️ 这是**项目制收入，不是 SaaS 收入**，销售周期 3–9 个月，**不要用它撑现金流**

**第 3 期 · SaaS 席位**（前置条件：求解器授权问题解决，或换 OpenFOAM/自研求解器）
- **授权问题解决之前，这一格只能是「假设」，不能是「计划」**

**★ 明确划掉**：把「短期：skills 包订阅」从第一位拿掉。
买 skills 包的人（DSH / agent 用户）和需要设计叶轮机械的人，**现在几乎是空集**——这是把你的分发方式误当成了客户的分发方式。
它可以降级为一条面向同行的副线（卖给其他 agent 开发者 / 想自建课题组），但**不能是主收入**。

## 3. 画布之外，精益创业还要求你显式写出的三样东西

### 3.1 信仰跳跃假设（Leap-of-Faith Assumptions）

**价值假设**
- V1：客户愿意为「**可审计、可自证的设计结论**」付钱，而不是为「更快的计算」付钱
- V2：客户愿意把第一次设计交给「agent + 人」的组合，而不是交给一位有名有姓的工程师

**增长假设**
- G1：内容 → 信任 → 首次试算 → 复购 这条链的转化率足以养活你
- G2：**单个算例的交付成本 < 售价**（含你自己的时间）

> 这四条，任何一条被证伪，画布都要重画。**最有风险的是 V2**——工程行业买的是「谁签字负责」，不是「谁算的」。

### 3.2 MVP 定义：**礼宾式 MVP（Concierge MVP），不是继续造软件**

- 找 3 个真实客户（1 个有真实节点的课题组 + 2 个做小型叶轮机械的硬件团队）
- 免费或成本价做 3 个算例，但**必须让他们签一张验收单**：
  结论是否被接受？哪一步你不信？你愿意为它付多少钱？愿不愿意介绍一个人？
- **同时记录：你在这三个案子里手动救火了多少次。**
  ★ 这个数字直接决定产品化优先级，是你最值钱的产品路线图。
- 30 天后做一次 pivot-or-persevere 决策。

**为什么不先做 SaaS**：SaaS 的前提是「客户自己会用」，而你的目标客户恰恰是「不会的人」。**先证明结论值钱，再决定要不要把它做成他们能自己用的形态。**

### 3.3 30 / 90 天节奏

| 时间 | 唯一目标 | 完成判据 |
|---|---|---|
