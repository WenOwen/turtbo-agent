问题

按「掏钱意愿」排序，用客户原话

  • P0 能力断层
    "师兄毕业了 / 招不到人，组里没人会 CFD，从头学要一年"
  • P0 交期压死
    "下周要评审，等超算、等外包、等师兄，来不及"
  • P1 结论不可信
    "算出来了，但一问网格无关性和收敛判据就崩"
  • P1 不可复现
    "同一个算例，两个人做出来两个结果"
  • P2 沉没成本
    "设计错了要重开模 / 重新试制，一次几万到几十万"

现有解决方案

  • 花钱招人 → 招不到；人走了知识跟着走
  • 靠老师傅经验 → 不可规模 / 不可审计 / 不可复现
  • 商业软件自带模板 → 给几何，不给判断
  • 外包代做（v1 漏）→ 不可追溯、改一次收一次钱。但它证明需求有预算，且它就是你 MVP 的形态
  • 通用大模型 + 一个懂行的人（v1 漏，增长最快）→ 差异化必须落在「正式工具链 + 可审计证据链」
  • 什么都不做，继续拍脑袋（最普遍）
v1：1.没人会　2.来不及　3.算不准

解决方案

按「客户能感知的价值」排序，不是按实现排序

  1. 一句话需求 → 结构化需求单（含「信息不足，算不了」的如实回答）
  2. 方案与几何自动生成：1D 通流 → 叶型 → geomTurbo
  3. 网格与求解全自动：AutoGrid / FINE + 质量报告 + 收敛判据
  4. 交付三表 + 一页结论，图可直接进 PPT
  5. 全程可审计：版本 / 哈希 / 上游 / 判据 / 结论，任一步可回放复现 ★护城河入口
  6. 可组合：可只买其中一段（例如「复核你现有的算例」）
v1：1.可组合 skills　2.自然语言驱动，小白可上手　3.可审计工作日志（内容对，但把"实现"当成了"价值"）

改写

独特价值主张

把「我想要一台 XX kgf 的风扇」做到一份能上评审会的 CFD 结论 —— 5 天，全程可追溯，每一步都有判据。

你不用会 CFD；
但你的结论经得起会 CFD 的人查。

10x 在哪：不是算得快（商业软件也算得快），而是
① 从「必须有人会做」到「不需要有人会做」
② 从「一坨结果」到「一条能自证的证据链」

不承诺什么（写进边界，避免过度承诺）：不承诺一次成功；不替代 CFD 工程师做最终判断；不替代试制前的人工评审。

v1：聊聊天就能设计出优秀的叶轮机械 —— "优秀"不可验证；"聊天"低估了价值

类比概念

给你的气动团队配一个不知疲倦的初级工程师，外加一个从不放过错误的审核员。

v1 的「工业设计软件的智能编排助手」是工具视角 —— 客户听完不知道自己省了什么。

· 对工程师："帮你把不敢签字的那部分补齐证据"

v1：工业设计软件的智能编排助手
重定义

不公平优势

判据只有一条：越用越厚，且抄不走。凡是能被一个足够强的团队在 6 个月内复制的，都不是。

  1. ★ 私有验证基准库（唯一带复利的资产）：v7 的 45 个验收点 + NASA 双级 900 点 + Rotor67 + DF90-001 全程。带真值的私有数据 = 模型标定 + "算得对不对"的自动判据
  2. ★ 验收判据库（闸门库）：知道"什么结果不能信"比"能算出来"稀缺得多，只能靠真项目一条条攒
  3. 全链关键环节自研：turbo-flow(1D/S2) + cascade-forge(造型) + 编排层
  4. ★ 数据飞轮：客户做得越多 → 基准库越厚 → 一次通过率越高 → 交付成本越低
  5. 自媒体信任资产：现在是 0（仓库无 remote、无发布痕迹）。只有持续发布才成立

如实承认的软肋

  • 核心求解器不是你的（NUMECA）
  • agent 编排能力正被通用模型快速拉平
  • 你只有一份时间 —— 服务型 MVP 的天花板
v1：1.气动知识+agent工程+工具链　2.跑通真实项目　3.自媒体信任资产（前两条是能力与证据，不是护城河）
具体化

渠道

  1. 自媒体：不发"我做了个 agent"，发带真值的过程复盘——"我用 AI 把 90 kgf 涵道风扇从需求做到 CFD 结论，第 3 天发现自己犯了什么错"。B站录屏 / 知乎 / 公众号
  2. ★ 学术圈口碑（你独有）：CompAI（AST 投稿中）+ DeepDelta-Aero（NASA 数据）—— 论文本身就是产品的可信度证明，且直连技术决策人
  3. 工具链生态：NUMECA / Ansys 代理商与培训渠道 —— 他们卖软件，你卖"买了软件还是没人会做"的那一段
  4. 硬件加速器 / 孵化器 / 低空经济产业园
  5. 案例客户转介绍：把"介绍一个人"写进验收单

渠道原则：每条渠道必须能算出「触达 100 人 → 几个留资 → 几个试算」。算不出来的渠道先不做。

v1：1.自媒体　2.学术圈口碑（方向对，但无法核算）
必须选边

客户群体

先做（收入）· 小型叶轮机械硬件团队

  • 5–30 人；有 1 名气动工程师，或干脆没有
  • 每年 2–5 个新叶型 / 新机型
  • 单次试制预算 5–50 万
  • 现状：SolidWorks + 外包 CFD，或自学 OpenFOAM
  • 行业：eVTOL / 无人机涵道风扇、小型涡喷涡扇、鼓风机压缩机、通风散热、泵与水轮机

明确不做（12 个月内）

  • 大型 OEM 气动室（他们有全套工具和人）
  • 纯教学用户 / 个人爱好者

为什么不能两个都要：课题组容易触达、会给你掌声、但不给你钱，且它的成功定义（能毕业 / 能发论文）与商业客户（能上评审会 / 能开模）不同。被"容易获得的客户"的正面反馈骗过去，是精益创业里最常见的死法。

v1：1.高校硕博课题组　2.企业工作室 —— 两个生意，一个 MVP 服务不了
重定义

早期采用者

已经吃过一次「设计错了要重开模」的亏，且下一次节点在 3 个月内的团队。

早期采用者 = 有痛点 + 有预算 + 有截止日期 + 愿意容忍不完美。
「高校课题组」不满足这个定义 —— 它只是容易触达。

战术性保留

所在高校 / 圈子里有真实课题节点、且愿意签验收单的课题组 —— 用来练手、积累案例库、做传播，不作为主要收入来源。

收入来源

原则：现金流优先，而不是想象力优先

第 0 期（0–3 月）· 算例代跑 / 交钥匙交付 —— 验证 + 现金流

  • 计价按「结论」而不是按机时；锚点：外包 CFD 一个涵道风扇算例市场价数千 ~ 数万，你落在「比外包便宜 30–50%，比自己做快 5 倍」
  • 节奏：首单免费 / 成本价（换验收单 + 案例公开授权）→ 第二单 5,000–15,000 元/交付 → 复杂机型 3–8 万
  • 为什么先做这个：一次拿到三样东西 —— 现金、真实需求、基准库数据

第 1 期（3–9 月）· 订阅式「气动外脑」

  • 2–5 万 / 年，含 N 个算例 + 随时问答 + 复核你已有的算例；卖的是"随时能问、随时能救火"

第 2 期（9–18 月）· 私有部署 + 定制

  • 客户有 license / 有机器 / 有保密需求 → 装进内网，部署费 + 年费（10 万级）
  • ⚠️ 这是项目制收入，不是 SaaS 收入，销售周期 3–9 个月，不要用它撑现金流

第 3 期 · SaaS 席位（前置条件：授权问题解决，或换 OpenFOAM / 自研）

  • 授权解决之前，这一格只能是假设，不能是计划

★ 明确划掉

  • 把「短期：skills 包订阅」从第一位拿掉。买 skills 包的人（DSH / agent 用户）和需要设计叶轮机械的人，现在几乎是空集 —— 这是把你的分发方式误当成了客户的分发方式。可降级为面向同行的副线，不能是主收入
v1：短期：skills包订阅+算例代跑　中期：私有部署个性化定制　长期：saas席位+算例代跑

信仰跳跃假设（Leap-of-Faith）

价值假设

  • V1：客户愿意为「可审计、可自证的设计结论」付钱，而不是为「更快的计算」付钱
  • V2：客户愿意把第一次设计交给「agent + 人」的组合，而不是交给一位有名有姓的工程师 —— 最有风险的一条（工程行业买的是"谁签字负责"，不是"谁算的"）

增长假设

  • G1：内容 → 信任 → 首次试算 → 复购，转化率足以养活你
  • G2：单个算例的交付成本 < 售价（含你自己的时间）

任何一条被证伪，整张画布都要重画。

MVP · 礼宾式，不是继续造软件

  • 找 3 个真实客户（1 个有真实节点的课题组 + 2 个做小型叶轮机械的硬件团队）
  • 免费 / 成本价做 3 个算例，但必须让他们签一张验收单：结论是否被接受？哪一步你不信？愿意为它付多少钱？愿不愿意介绍一个人？
  • ★ 同时记录：你在这三个案子里手动救火了多少次 —— 这个数字直接决定产品化优先级，是你最值钱的产品路线图
  • 30 天后做一次 pivot-or-persevere 决策

为什么不先做 SaaS：SaaS 的前提是"客户自己会用"，而你的目标客户恰恰是"不会的人"。先证明结论值钱，再决定要不要把它做成他们能自己用的形态。

30 / 90 天节奏

时间唯一目标
第 1 周打三个电话：NUMECA 授权范围 + 2 个潜在客户的真实节点
第 2–4 周把 DF90-001 真正闭环到 G6 交付（现在停在 G5）
第 5–8 周3 个礼宾式算例 + 3 张验收单；判据：至少 1 个客户主动问"下一个多少钱"
第 9–12 周记录在案的 pivot-or-persevere 决策；定价与合同模板定稿

你现在最该做的一件事，不是再写 10 个 skill，而是把 DF90-001 从 G5 推到 G6，并让一个真人签收。它同时解决三件事：验证 UVP、拿到案例、填上「关键指标」的第一行基线。
