# 涵道风扇专用硬合同（C-001 …）

> 每条都带 **来源** 与 **适用边界**。**适用边界为空或写"通用"的条目一律视为不合格。**
> 判据缺失来源时，闸门必须报错而不是放行。
>
> **可机检的条目带"机读"块 —— 那是闸门判据的唯一真源。**
> `tools/gate_check.py` 从这里读阈值、允许值和绑定关系，代码里**不另写一份**。
> 改了合同就是改了判据，不存在两处不一致。
> 一致性自检：`python tools/gate_check.py audit --case <案例ID>`
> 它会报出"合同声明了但代码没实现""代码实现了但没合同""gate 与 check 编号不匹配"。
>
> 没有机读块的条目是**人判规则**（如 C-005 落后角符号、C-009 y+ 判据），
> 闸门检查不了，靠 agent 读 skill 时遵守。

## C-001 转子轴功率必须用旋转壁面扭矩

**人话**：算轴功率只能用「会转的壁面」受到的扭矩去乘转速。机匣和静子也受力，但它们不转，所以它们身上的力矩不产生功率。

**当初为什么加**：NUMECA 默认的 allwalls 扭矩把机匣和静子也算进去了，直接用会高估轴功率。

**合同**
XMF 的 `Torque` 若来自 `allwalls` 选择，包含机匣与静子壁面，**不得**整体乘以转子角速度当轴功率。
静止壁面虽可承受力矩，但角速度为零，不贡献轴功率。

**合法替代方案**（三选一，注明用的是哪个）
1. 仅对转子旋转叶片 / 旋转轮毂做力矩积分
2. 转子进出口控制面的角动量通量差
3. 转子进出口总焓升功率（明确它不是直接壁面积分轴功率）

**复核清单**：周期扇区、叶片数缩放、转速符号、站位定义——四项同时核对。

**来源**：`Ducted-Fan/0-caseDict/memory.md#2026-07-23`（用户确认）
**适用边界**：任何含静止壁面的叶轮机械算例。低背压下扭矩换号时，这个合同尤其关键。

## C-002 出口静压扫点：末段质量流量稳定性是主判据

**人话**：判断一个算例算完没有，看最后一段进口和出口的流量稳不稳（各自波动不超过 0.2%），不看残差降到几。残差只用来发现算炸、出 NaN、持续恶化。

**当初为什么加**：旧队列拿残差当硬门槛，误拒了 5 个本来稳定的点，还提前掐断了低背压的续算链。

**合同**
压力扫点**不得**用固定残差值作主收敛判据。判据为：

| 项 | 阈值 | 性质 |
|---|---|---|
| 末段窗口 `MF_IN`、`MF_OUT` 各自 `100×(max−min)/|mean|` | ≤ **0.2%** | 本工程合同 |
| 最终质量不平衡 `100×|ṁ_in−ṁ_out|/|ṁ_in|` | ≤ **1%** | 本工程合同 |
| 正常结束 + CGNS 存在 + 无关键日志错误 | 布尔 | 硬 |

残差**只**用于识别 NaN、爆炸、持续恶化，不设 RMS/MAX 绝对硬门槛。

**血泪教训**：旧队列的残差硬门槛造成 5 个稳定点被误拒绝，并让低背压续算链提前中断；
同时有 3 个旧 "accepted" 点的质量流量仍明显波动。

**续算依赖必须用与最终验收相同的合同**。不得仅因 RMS/MAX 未达经验值就跳过后续背压点，
否则会人为截断堵塞端或失速侧包络。

**机读**（闸门判据的唯一真源；`gate_check.py` 从这里读阈值，不另写一份）：

```yaml
gate: G5
check: G5-3
mass_error_limit_pct: 1.0
range_limit_pct: 0.2
```

**来源**：`memory.md#2026-07-27`（用户纠正）｜复核入口 `D-post/postprocess.py`
**适用边界**：**0.2% 与 1% 是当前项目的暂定工程合同，不得无条件泛化。** 换机器/换网格族时必须重新标定并在 LOG.md 注明。

## C-003 交付参数表是工程表，不是审计日志

**人话**：交给别人的表格里不许出现本地文件路径、版本号、质量状态这类字眼。某个指标在所有工况都没数，就整行删掉；只有部分缺，才填一个破折号。

**当初为什么加**：交付表是工程表，不是审计日志。审计信息另存文件，两者不能混。

**合同**
最终三表**不得**出现：本地文件路径、来源文件名、算例版本号、重复角色、逐行质量说明、
`CFD质量状态`、`质量状态`、`警告`、质量原因字段。

**性能表结构**：前三列固定为 `参数类别 / 参数名称 / 单位`，其后每个工况一列，列名形如 `背压 103000 Pa`。
一行只出现一次指标。某指标在**全部**工况无有效值时**直接省略**（例如没有 y+ 数据就不建 y+ 字段）；
仅部分工况缺失时才保留该指标并以 `—` 表示缺值。

**收敛与完整性检查仍必须在程序内部执行**，发现问题在任务反馈里说明，但**不占用参数表字段**。

**机读**（闸门判据的唯一真源；`gate_check.py` 从这里读阈值，不另写一份）：

```yaml
gate: G6
check: G6-2
banned: CFD质量状态 | 质量状态 | 警告 | sha256
banned_drive_prefix: true
```

**来源**：`memory.md#2026-08-04`（用户纠正）×2
**适用边界**：所有对外交付表。内部审计另存 `*_audit.json`，两者不混。

## C-004 整机静推力只认控制体口径

**人话**：整台风扇的推力 = 出口流出去的动量 + 出口截面上的压力差。不是 NUMECA 里那个壁面轴向力——它只算了转子叶片和转子轮毂受的力。

**当初为什么加**：用壁面力当整机推力会让结果差几十牛，而方案可能就差这几十牛。两项加起来对不上时，停下来报告，不许退回壁面力。

**合同**

```
T = ṁ_out · Vx_out + (p_out − p_∞) · A_out
    └─ 动量推力 ─┘   └─── 压力推力 ───┘
```

- 静止环境静推固定为 `V_∞ = 0`、`p_∞ = 0 Pa(g)`；环境绝对静压由命令行传入。
- 出口必须是用**户确认的涵道出口边界**，不得用转静接口或壁面力代替。
- `Vx_out` 用 XMF Outlet 的质量加权轴向速度。
- 对定静压出口，压力项用**真实全周出口面积**：CFView 周期扇区面积必须乘以出口叶排周期数，
  并与轮毂/机匣半径解析环面积交叉核验。

**强制闭合检查**：`static_thrust_n = momentum_thrust_n + pressure_thrust_n`。
不闭合或数据缺失 → **停止并报告**，**不得回退到壁面轴向力。**

**禁止**：把 XMF 壁面"轴向推力"当整机净推力。它只积分转子叶片与转子轮毂。
交付表中的参数名统一为 **「轴向推力（动量+压力）」**。

**机读**（闸门判据的唯一真源；`gate_check.py` 从这里读阈值，不另写一份）：

```yaml
gate: G0
check: G0-4
also_check: G6-3
allowed_definition: control_volume | wall_axial_force
default_definition: control_volume
closure_tol_rel: 0.000001
```

**来源**：`memory.md#2026-08-04`（用户纠正）
**适用边界**：截断涵道控制域内的静推估算。**不得**声称为完整外流场/完整涵道的直接壁面积分净推力。

## C-005 落后角必须先统一气流角与金属角符号坐标系

**人话**：如果算出来的落后角有 70 到 140 度那么大，先别急着说叶片失速——十有八九是两个角度用了相反的转向定义，直接相减出来的假象。转子要相加，静子要相减。

**当初为什么加**：这个量级不是物理现象，是符号合同错误。统一坐标系后还超过 30 度，才去看真实流动。

**合同**

```
转子：delta_r = beta2 + CAMBER_BETA2
静子：delta_s = alpha2 − CAMBER_BETA2
```

物理含义统一为「出口气流角减同坐标系尾缘中弧线金属角」。

**诊断顺序**（不可颠倒）：
1. 若直接相减产生约 **70°–140°** 的转子"落后角"，**优先判定为符号合同错误**，
   不得解释成真实分离或失速。
2. 映射到同一坐标系后仍超过约 **30°**，才结合回流率、速度矢量、尾迹、端壁分离继续诊断。

**已验证实例**：`mesh-v6_p103000_allwalls` 修正后转子带符号角差 −11.33°…−8.36°
（按欠转为正 = 8.36°…11.33°），静子 9.90°…18.02°，两排进出口回流率均为 0。

**来源**：`memory.md#2026-08-12`（用户发现 + 复核确认）
**适用边界**：**30° 仅作异常筛查，不是通用设计判据。** 当前合同只对已验证的两排转子—静子拓扑成立；
换拓扑必须重新审计控制面与符号约定。

## C-006 FINE 参考量必须从算例推导，禁止保留 GUI 默认

**人话**：FINE 里那个特征长度、特征速度、特征密度，不能留着默认的 1 米、10 米每秒、1.2 千克每立方米。要用这个算例自己的弦长、叶速、密度填进去。

**当初为什么加**：默认值是 GUI 给的占位符，会让雷诺数错到离谱。2026-09-18 核对发现原合同的来源文件在本链路根本不存在，已改指向本链路的产物。

**合同**
FINE/Turbo 要的 Reynolds 参考量**不得**保留 GUI 默认（`1 m`、`10 m/s`、`1.2 kg/m3`）。

**来源列必须指向本工作流的产物**（下表已按 DF90-001 链路重新指向；
原合同引自 CompAI 线，那里的 `section_schedule.csv` 在本链路**不存在**）：

| 量 | 取法 | 本链路的来源列/文件 |
|---|---|---|
| Characteristic length | 转子/静子的**平均弦长** | `01-scheme/vN/叶片几何参数表.csv` 的 `弦长(m)` 列 |
| Characteristic velocity | 优先 `sqrt(Va² + U_mid²)` | `Va` 取自 `通流计算结果表.csv`；`U_mid = ω·r_mean`，`r_mean` 取自 `流道尺寸表.csv` 的 `中径半径(m)` |
| Characteristic density | 入口/平均密度 | `requirements.yaml` 的 `environment.density_kg_m3`，或平均线输出的近入口均值 |

必须在 case notes 或 manifest 里记录取值**及其来源列/文件**。

**参考实例（外来项目，勿照抄数值）**：`fptip_024_stator_trim_004` 属 CompAI 线 →
长 0.08 m（弦长 0.078–0.084）、速 100 m/s（Va≈56.9，5300 rpm 中径叶速≈103）、
密度 1.21 kg/m³，Re ≈ 5.4e5。**仅用于校验量级，其数值不得跨算例复制。**

**来源**：`numeca-cfd-workflow/SKILL.md`「FINE/Turbo Reference Quantities」
（2026-09-18 全语料核对：`section_schedule.csv` 与 `fptip_024_stator_trim_004`
在 Ducted-Fan 下 0 命中，均属 CompAI 线，故重新指向本链路产物。）
**适用边界**：所有 FINE/Turbo 算例。具体数值不可跨算例复制。

## C-007 一个唯一网格 ↔ 一个独立 `.iec`

**人话**：一个网格只能配一个 FINE 工程文件。换了网格就必须新建工程，不能把新网格的算例挂在旧工程底下。

**当初为什么加**：FINE 工程文件才是「这个工程里有哪些算例」的唯一真源；磁盘上多出来的算例文件不会自动写回工程里。

**合同**
网格身份由**规范化 `.igg` 路径 + SHA256 + 块签名**共同确定。
不同网格**不得共用**同一个 `.iec`。新增粗/中/细网格必须分别新增 `.iec`。

**配套硬规则**
- `.iec` 是 FINE 工程内 computation 清单的**规范来源**；目录和独立 `.run` **不会**自动回写 `.iec`。
- 同一网格的**全部** computation 必须同步回该网格的 `.iec`：创建/复制/重命名/删除 `.run` **前**，
  先在 `.iec` 完成同名操作，保存并**重新打开验证**。
- 界面删除 computation 后必须保存 `.iec` 并重开验证；删除目录**不会**删除 `.iec` 内的 computation。
- **FINE computation 必须用 ICE 原生同级目录合同**：
  工程 `<root>/<project>.iec` + computation `<name>` → 所有 `.run/.res/.cgns/.mf/.xmf/.log/.std`
  归属 `<root>/<project>_<name>/`，主运行文件为 `<project>_<name>.run`。
  **禁止**把多个工况平铺进共享 `computations/`。

**机读**（闸门判据的唯一真源；`gate_check.py` 从这里读阈值，不另写一份）：

```yaml
gate: G4
check: G4-5
```

**来源**：`numeca-fine-solver/SKILL.md` 强制原则 12–15
**适用边界**：NUMECA FINE/ICE 16.1。其它版本需重新确认。

## C-008 状态词必须五档区分

**人话**：「已准备」「已排队」「正在跑」「跑完了」「验完了」是五件不同的事，不能混着说。进了迭代只能叫「正在跑」，不能叫「算完了」。

**当初为什么加**：正常结束不等于收敛。求解器退出码是 0，也不代表结果能用。

**合同**
严格区分：`已准备 / 已排队 / 正在运行 / 已正常退出 / 已验收`。

- 进入迭代 = **正在运行**，不得写成"计算完成"
- 正常结束标记 ≠ 收敛证明
- 求解结束后先置 `finished_unverified`，做完数值验收才更新为 `accepted` 或 `rejected`

**来源**：`numeca-fine-solver/SKILL.md` 强制原则 5–6
**适用边界**：通用。

## C-009 y+ 在未确认壁面处理前不判 PASS/FAIL

**人话**：y+ 只是一个数，记录下来就行。在没搞清楚用的是壁面函数还是低雷诺数解析之前，不能拿它判合格不合格。

**当初为什么加**：同一个 y+ 值，在不同的壁面处理下含义完全不同。

**合同**
`checks.csv` 中 y+ **仅记 INFO**。未确认壁面处理（壁面函数 vs 低雷诺数解析）前，
不得据此判 PASS/FAIL，也不得宣称"y+ 合格"。

**来源**：`numeca-cfview-post/SKILL.md` 固定检查项
**适用边界**：通用。已确认壁面处理且用户明确要求时，可另行定义判据并注明来源。

## C-010 交付三表之外的审计信息不得丢弃

**人话**：交付表要干净，但不等于审计信息可以扔掉。收敛、完整性、闭合检查的结果要落到单独的机器可读文件里，逐点写清是哪一项、什么值、什么阈值触发的。

**当初为什么加**：C-003 管的是「给别人看什么」，这一条管的是「自己留什么」。两件事都要做。

**合同**
C-003 要求交付表干净，但**不等于**审计信息可以不存。收敛、完整性、数据闭合检查结果必须
落到机器可读文件（`checks.csv`、`*_audit.json`、`operating_points.csv` 的 `quality_reasons` 列），
并逐点记录触发项、数值与阈值。

**来源**：`memory.md#2026-08-04` + `numeca-cfview-post` 工况图规则
**适用边界**：通用。

## C-011 振荡侧边界必须区分「策略拒绝」与「人为停止」

**人话**：找「算到哪个背压就振荡了」的时候，条件是「比最后一个验收点更高的第一个没验收的点」，不能写死成「状态等于 rejected」。因为同一个现象有两种记法：机器自己判的，和人喊停的。

**当初为什么加**：2026-09-17 我写的判据只认 rejected，在 v7 的 5000 转上误报失败——那个点是人喊停的（stopped/user_stop），不是机器判的。把两个字段串成 stopped/persistent_flow_oscillation 更错，那个组合从没出现过。

**合同**

审计"振荡侧边界"时，判据是**「高于最高验收背压的第一个未验收点」**——
**不是** `state == "rejected"`。同时必须**同时保留该点的 `state` 与 `reason`**，
因为同一个物理现象有两种记录方式：

| 触发来源 | `state` | `reason` |
|---|---|---|
| 求解器按策略自动判定 | `rejected` | `persistent_flow_oscillation` |
| 用户要求保存停止 | `stopped` | `user_stop` |

**两者不得视为等价**：`rejected` 是策略判定，`stopped` 是人为干预，审计语义不同。
交付文档若用自然语言写"首个振荡背压"而不给状态码，必须回查原始汇总表确认是哪一种。

**已验证实例**：`90kg-duct-fan-v7` 的 `sweep_summary.csv` 中，
4500 / 5500 rpm 的边界点是 `rejected` + `persistent_flow_oscillation`，
而 5000 rpm 的 103525 Pa 是 `stopped` + `user_stop`
（`README-CFD.md` 记载该点在持续振荡时由用户要求正常保存停止，
末 3000 步流量 8.540–8.893 kg/s、各 500 步窗口相对极差约 4.04%、振幅不衰减）。
`CFD-DELIVERY.md` 的同一列把两者都称作"首个振荡背压"，未区分状态。

**反例（错法）**：把两个字段串成一个 `stopped/persistent_flow_oscillation` ——
这个组合在 v7 数据里**从未出现**。

**机读**（闸门判据的唯一真源；`gate_check.py` 从这里读阈值，不另写一份）：

```yaml
gate: G5
check: G5-5
attributed_states: rejected | stopped
unattributed_marker: unknown
```

**来源**：`cases/DF90-001/memory.md#2026-09-17`（回放审计 R-8 首次报 FAIL 时发现）
**适用边界**：凡交付物用自然语言描述"边界"而非直接给状态码的场合；
以及任何"工具输出状态 + 原因"分列的汇总格式。
