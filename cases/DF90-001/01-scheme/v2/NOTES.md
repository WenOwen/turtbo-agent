# DF90-001 · 01-scheme/v2 来源说明

## 这一版在解决什么

案例里有两台机器：`01-scheme/v1` 三表和 `verification_plan.first_point` 锚点说的是 **v7**
（入口轮毂 0.103457），而 `02-geometry/v8` 几何是**另一台**（入口轮毂 0.08，人工调过）。
`gate_check.py geometry` 判 FAIL（G3-5 / G3-9）。

v2 的目标：**把 G2 的方案做成一套完整的、可推几何的、且显式满足电机包络的设计**，
让 G3 能直接由它导出几何，而不是再手工调。

## 两个反解出来的结论（都不是随手选的）

### 1. 入口轮毂半径 = 0.103457，由设计流量系数反解

```
phi_tip = 0.2581            (v1 输入口径)
U_tip   = 638.791 * 0.3 = 191.637 m/s
Va      = 0.2581 * 191.637 = 49.462 m/s
A_in    = 15.09343 / (1.225 * 49.462) = 0.249106 m2
r_hub   = sqrt(0.3^2 - 0.249106/pi) = 0.103475 m
```

取 **0.103457**（与 v1 参数表 INLET 一致，差 0.018 mm = 舍入）。
**它不是自由变量** —— 换一个值就等于换了设计流量系数。

### 2. 流道长度 180.135 -> 240 mm：因为 v1 的长度装不下叶排

```
两排各 chord = 0.090 m，排间间隙 0.020 m
至少需要 2*0.090 + 0.020 = 0.200 m
v1 的流道长度 = 0.180135 m  ->  装不下
```

**v8 把流道加到 300 mm 是对的方向，但它给的理由（电机包络）并不成立** ——
电机包络只要求 95 mm 的圆柱段，不要求把流道拉长。
加长的真实原因是**叶排占位**。

## 一个还没有答案的问题

**G2 从来不算推力。** `通流计算结果表.csv` 里有流量、压比、效率、功率、扭矩，**没有推力**。
而需求 ACC-1 是推力（882.60 N）。B-1..B-7 七条判据里也没有一条是推力。

把 ACC-1 的公式硬套在叶排域出口（`OUTLET` 站，x=0.240）上会得到 **1400.96 N = 142.86 kgf**（+58.7%），
但这个数**不可用**：C-004 要求「出口必须是用户确认的**涵道出口边界**」，
而 `OUTLET` 是叶排域末端，其上游还有 2666 Pa 的静压盈余 ——
涵道怎么处理这段压力（扩张 / 收缩 / 直接排出）决定了最终推力，而 1D 方案里没有涵道模型。

**所以 90 kgf 这个问题，G2 目前答不了。** 见交付说明。
