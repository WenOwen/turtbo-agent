## 三、静推力三列（C-004）+ `A_out` 交叉核验

`python tools/thrust_closure.py`（合同 C-004 公式，**逐字遵守**）

```
静推力 = mdot_out * Vx_out + (p_out - p_inf) * A_out
         └─ 动量推力 ─┘   └─── 压力推力 ───┘
```

### 3.1 三列实测（`04-solve/v3/g5/thrust_closure.csv`）

| 列 | 值 |
|---|---|
| **`static_thrust_n`** | **566.6042417 N** |
| **`momentum_thrust_n`** | **566.6769851 N** |
| **`pressure_thrust_n`** | **−0.072743385 N** |
| `static_thrust_kgf` | **57.77755316 kgf** |
| `closure_rel_err` | 0 |

代入数（全部来自 `.xmf` 的 **Outlet** 站位）：

| 量 | 值 |
|---|---|
| 出口质量流量 `mdot_out` | 12.89682 kg/s |
| 出口轴向速度 `Vx_out` | 43.93928 m/s |
| 出口静压 `p_out` | 101324.7 Pa |
| 环境静压 `p_inf` | 101325 Pa（requirements.yaml，`assumed`） |
| 全周出口面积 `A_out` | 0.24247795 m² |

动量推力 = 12.89682 × 43.93928 = **566.6769851 N**
压力推力 = (101324.7 − 101325) × 0.24247795 = **−0.072743385 N**
静推力 = 566.6769851 + (−0.072743385) = **566.6042417 N = 57.78 kgf**

### 3.2 `A_out` 交叉核验（任务书要求：相对差应在 1e-4 量级）

**三方独立来源：**

| # | 来源 | 值 (m²) |
|---|---|---|
| ① | 求解器周期扇区面积 × 出口叶排周期数 = 0.02204345 × **11** | **0.24247795** |
| ② | 解析环面积 π(r_shroud² − r_hub²) = π(0.3² − 0.1132²) | **0.2424862166** |
| ③ | 方案表 `01-scheme/v4/流道尺寸表.csv` OUTLET 通流面积（独立文件） | **0.242486** |

- ① vs ② 相对差 = **3.4091e-05** → **PASS**（工具阈值 0.5%）
- ② vs ③ 相对差 = **8.9e-07**（受 ③ 只写 6 位小数限制）

**→ `A_out` 成立，正是任务书说的 1e-4 量级，且是三方互证而不只是两方。
这是「几何 + 方法」的结论，与流场收不收敛无关。**

周期数取 `.xmf` Outlet 站位的 `Number of blades = 11`，与 G3 记录的 S1 叶排 11 片一致。

### 4.2 ⚠ 这条 FAIL **不能**读成「这台机器不达标」—— 三个口径陷阱（我实测查出来的）

**陷阱 ①：工具的「环形几何同源」是自洽检查，不是血统检查。**

工具的几何基线取自 `01-scheme/**v4**/流道尺寸表.csv`（`latest_version` 取最新版），
而 **v4 就是本次 CFD 自己的方案**。所以四条「0.0000% PASS」证明的是
**「CFD 几何 = 当前方案表」**，**不是「CFD 几何 = v7 锚点机器」**。

**工具打印的那句理由已经过期**：
> 方案表与 v7 锚点同源：INLET 轮毂 0.103457 对 v7 XMF 的 0.1034572，OUTLET 轮毂 0.125500 对 0.125167（0.27%）

**但 v4 的实际值是 INLET 0.08 / OUTLET 0.1132 —— 不是 0.103457 / 0.125500。**
这句写死在代码里的解释文字，在 v4 上已经不成立了。

**陷阱 ②：真正的 v7 锚点几何，与本次不是同一台机器。**（我直接读了 v7 的 `.xmf`，只读）

| 站位 | 项 | **v7 锚点实测** | 本次实测 | 相对差 |
|---|---|---|---|---|
| Inlet | 轮毂半径 | **0.103457** | **0.080000** | **−22.67%** |
| Inlet | 机匣半径 | 0.300000 | 0.300000 | 0.00% |
| Outlet | 轮毂半径 | **0.125167** | **0.113200** | **−9.56%** |
| Outlet | 机匣半径 | 0.300000 | 0.300000 | 0.00% |

**→ 环形几何不同源（远超 2% 观察带）。** 所以：
**那条 torque FAIL 只能读成「与 v7 锚点不可比」，不能读成「本机达不到锚点」。**
（同一个道理，mdot −4.46% 与 PR −0.20% 也含跨血缘成分。）

**陷阱 ③：容差来自另一个工况的文件。**

`tol_efficiency_abs = 0.02` / `tol_torque_rel = 0.05` 取自
`01-scheme/v4/inputs/benchmark-targets.json` —— 那是 **6100 rpm 设计点**的文件
（`rpm: 6100`，`mass_flow_kg_s: 15.09343`，`total_pressure_ratio: 1.041818`，`torque_nm: 90.32`）。
**拿 6100 rpm 设计点的容差去判 5000 rpm 锚点的偏差，本身就是第二次口径错配。**

**综合结论：G5-6 的 FAIL 是真实的工具输出（我不改它），但它的正确解读是
「本次求解与 v7 锚点跨血缘、且容差来源工况不同 —— 这条对照当前不可用于判达标」。**
